# Deploying AfriSend with no terminal

Everything here is done in a web browser. The only exception is one command for
the mobile app (Part 6), and that runs in a browser-based terminal, not on your
machine.

**Order matters:** database → API → console → Flutterwave → app.

| Part | What | Where | Time |
| --- | --- | --- | --- |
| 1 | Put the code on GitHub | github.com | 5 min |
| 2 | Create the database | supabase.com | 10 min |
| 3 | Deploy the API + console | render.com | 15 min |
| 4 | First sign-in and setup | your API's `/admin` | 10 min |
| 5 | Connect Flutterwave | dashboard.flutterwave.com | 10 min |
| 6 | Build the iOS + Android apps | expo.dev + GitHub Actions | 30 min |

---

## Part 1 — Put the code on GitHub (no git commands)

1. Download `afrisend.zip` and **extract it** (double-click; you get an `afrisend`
   folder).
2. Go to **github.com** → sign in → **+** (top right) → **New repository**.
3. Name it `afrisend`, choose **Private**, click **Create repository**.
4. On the empty repository page click **uploading an existing file**.
5. Open the extracted `afrisend` folder, select **everything inside it** (not the
   folder itself), and drag it onto the GitHub upload area.
6. In the "Commit changes" box type `Initial commit` → **Commit changes**.

> The archive deliberately contains no `.env` file, no `node_modules` and no
> secrets, so it is safe to upload as-is. If GitHub complains about a folder
> being empty, ignore it — Git does not track empty folders.

---

## Part 2 — Create the database (Supabase)

1. **supabase.com** → sign in → **New project**.
   * Name: `afrisend`
   * Database password: click **Generate a password** and **save it somewhere safe**
     (you need it in Part 3)
   * Region: **Frankfurt** (closest to Doha of the available regions)
2. Wait for provisioning (~2 minutes).
3. Left sidebar → **SQL Editor** → **New query**.
4. Open `supabase/INSTALL.sql` from the extracted folder in any text editor
   (Notepad, TextEdit, VS Code, even a browser tab) → **select all → copy**.
5. Paste it into the SQL editor → **Run** (or Ctrl/Cmd + Enter).
   You should see **"Success. No rows returned"**. This creates all 39 tables and
   is safe to run twice.
6. Left sidebar → **Project Settings** (gear) → **Database** → **Connection
   string** → choose the **Session pooler** tab → **Copy**.
7. Replace `[YOUR-PASSWORD]` in the copied string with the password from step 1,
   and keep the result for Part 3. It looks like:

   ```
   postgresql://postgres.abcdefghijklm:YOURPASSWORD@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```

> **Optional but recommended for a regulated ledger:** Project Settings →
> Database → **Point in Time Recovery** → enable (paid add-on).

## Part 3 — Deploy the API and console (Render)

1. **render.com** → sign in with GitHub → **New +** → **Blueprint**.
2. Pick your `afrisend` repository → **Connect**. Render reads `render.yaml` and
   shows a service called **afrisend-api**.
3. Click **Apply**. Render now asks you to fill in the variables marked as
   secrets. Use these values:

   | Field | What to enter |
   | --- | --- |
   | `DATABASE_URL` | the Supabase **Session pooler** string from Part 2 |
   | `JWT_SECRET` | click **Generate** if offered, otherwise paste 64 random characters (e.g. from your password manager: generate a 64-character hex password) |
   | `JWT_REFRESH_SECRET` | a **different** 64 random characters |
   | `PII_ENCRYPTION_KEY` | leave as generated by Render |
   | `PII_HMAC_KEY` | leave as generated by Render |
   | `FLW_SECRET_KEY` | Flutterwave → Settings → API Keys → **Secret key** |
   | `FLW_PUBLIC_KEY` | Flutterwave → Settings → API Keys → **Public key** |
   | `FLW_WEBHOOK_HASH` | make one up now (e.g. 24 random characters). You paste the **same** value into Flutterwave in Part 5 |
   | `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` / `TWILIO_FROM_NUMBER` | from twilio.com → Console. Until these are set, customers cannot receive OTP codes |
   | `RIA_*` | leave blank unless you have Ria credentials (cash pickup) |
   | `BOOTSTRAP_ADMIN_EMAIL` | **you@yourcompany.qa** — the first operator account |
   | `BOOTSTRAP_ADMIN_PASSWORD` | at least 12 characters with 3 of: lowercase, uppercase, digits, symbols |
   | `BOOTSTRAP_CORRIDORS` | your Treasury rates, see below |
   | `BOOTSTRAP_SANCTIONS_URLS` | a sanctions list, see below |
   | `QCB_LICENSE_NUMBER`, `MLRO_NAME` | your licence and MLRO — printed on QCB filings |

4. `BOOTSTRAP_CORRIDORS` — **use your own Treasury numbers**. `CODE=BASE_RATE`
   and the platform keeps a 1.5% margin automatically, or `CODE=BASE/RETAIL` if
   you want to set both:

   ```
   NGN=421.06, GHS=4.28, KES=35.55, UGX=1018.40, TZS=724.80, RWF=394.50, XOF=165.20, XAF=165.20, EGP=13.38
   ```

   These run **only while the corridor table is empty**, so you can leave the
   variable in place forever. After that, changes go through the console
   (Treasury → propose rate change → a second operator approves).

5. `BOOTSTRAP_SANCTIONS_URLS` — screening cannot clear a transfer until at least
   one list is loaded. Format `SOURCE|URL`, comma separated:

   ```
   OFAC_SDN|https://www.treasury.gov/ofac/downloads/sdn.csv
   ```

   The import runs only while the list table is empty. A CSV needs a `name`
   column; optional columns are `aliases` (`|` separated), `dob`
   (`YYYY-MM-DD`), `nationality` (two letters), `reference`.
   If a URL is unavailable the API still starts and logs the reason — you can
   import later from **Compliance → sanctions** in the console.

6. Click **Deploy**. First build takes ~5 minutes.
7. When it says **Live**, note your URL, e.g.
   `https://afrisend-api.onrender.com`. If Render gave the service a different
   name, open **Environment** and correct `PUBLIC_BASE_URL` and `CORS_ORIGINS` to
   the real URL, then **Save changes** (it redeploys).

8. Open **Logs** and look for these lines — they tell you the bootstrap worked:

   ```
   "msg":"first-run bootstrap complete"
   "msg":"sign in at /admin with your operator account"
   ```

   If you instead see `NO OPERATOR ACCOUNT YET` or `NO CORRIDORS PROVISIONED`,
   the corresponding variable is missing or mistyped — fix it in **Environment**
   and redeploy. Nothing is guessed for you.

## Part 4 — First sign-in and setup (all in the console)

Open **`https://<your-api>/admin/login.html`** and sign in with
`BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD`.

Then, in this order:

1. **Security** (top right) → **Enable MFA** → add the secret to Google
   Authenticator / Authy / 1Password → enter the 6-digit code → **Activate MFA**.
   From then on every sign-in asks for the code.
2. **Security → Add operator** → create a **second** account (e.g. your MLRO as
   `COMPLIANCE_MLRO`). Four-eyes approvals need two different people; one account
   alone cannot approve its own requests, by design.
3. **Treasury** → check the corridors and rates are what you intended.
4. **Customers** → credit a wallet when a customer deposits by bank transfer and
   you have verified it against the bank statement — this posts a ledger entry
   and is audited.
5. **Compliance** → **Generate AML return** to produce your first signed QCB
   filing.

> To deactivate the bootstrap permanently: edit `BOOTSTRAP_ADMIN_PASSWORD` in
> Render → Environment, clear the value, save. It is harmless either way (the
> step only runs when there are no operators at all), but there is no reason to
> keep a password in the dashboard.

## Part 5 — Connect Flutterwave (webhooks)

1. **dashboard.flutterwave.com** → **Settings** → **API Keys** — make sure the
   `FLW_SECRET_KEY` / `FLW_PUBLIC_KEY` you set in Part 3 are the **live** keys.
2. **Settings** → **Webhooks**:
   * **URL**: `https://<your-api>/api/v1/webhooks/flutterwave`
   * **Secret hash**: the exact same string you put in `FLW_WEBHOOK_HASH`
   * **Events**: `charge.completed`, `transfer.completed`, `transfer.failed`,
     `transfer.reversed`
3. Save, then pay a small test amount through the app: the wallet should credit,
   and **Compliance → webhooks** in the console should show the event with
   **signed**.
4. Payments that fail signature verification appear there as **rejected** and are
   written to the audit trail — no money moves.

## Part 6 — Build the iOS and Android apps

The app is built by **EAS** (Expo's build service). You need one value that EAS
generates — the project ID — and one command creates it.

### 6a. One command, in a browser terminal (nothing to install)

1. **expo.dev** → sign up / sign in.
2. **expo.dev/settings/access-tokens** → **Create token** → copy it (you need it
   in 6b).
3. On **github.com**, open your `afrisend` repository → green **Code** button →
   **Codespaces** tab → **Create codespace on main**.
   A VS Code window opens in your browser with a terminal at the bottom.
4. In that terminal type these three lines (this is a cloud machine, not yours):

   ```
   npm install -g eas-cli
   eas login
   eas init
   ```

   Answer `yes` when it offers to create the project. It writes the generated
   `projectId` into `app.json` for you.
5. Commit the change from the same window: **Source Control** icon (left
   sidebar) → type `Link EAS project` → **Commit** → **Sync Changes**
   (or use the ⇧⌘G panel; GitHub will offer **Commit & Push**).
6. Close the Codespace. You will not need it again unless you edit native code.

### 6b. Let GitHub build and publish the download links

1. **github.com** → your repository → **Settings** → **Secrets and variables** →
   **Actions** → **New repository secret**. Add two:
   * `EXPO_TOKEN` — the token from step 6a.2
   * `EXPO_PUBLIC_API_URL` — `https://<your-api>/api/v1` (the URL from Part 3)
2. **Actions** tab → **EAS Build (iOS + Android)** → **Run workflow**:
   * `profile`: **preview** (installable APK + iOS internal build)
   * `platform`: **all**
   * `submit`: false
   → **Run workflow**.
3. Wait ~15–25 minutes. When it finishes, open the run → the **Summary**
   contains a table with a **build page** and **download link** for each platform:
   * **Android** — the `.apk` installs directly on any phone.
   * **iOS** — the `.ipa` installs on devices registered in your Apple Developer
     account (Expo will guide you through adding them the first time).
4. For the store versions, run the workflow again with `profile: production`
   (Android App Bundle for Play, iOS archive for the App Store) and
   `submit: true` once your store credentials are set up.

Want to try the app before building anything? In the browser terminal from 6a,
run `npx expo start --tunnel` and scan the QR code with **Expo Go** on your phone.

## Troubleshooting (all from the browser)

| Symptom | Where to look | Meaning |
| --- | --- | --- |
| Console shows *"No corridors provisioned"* | Render → Logs | `BOOTSTRAP_CORRIDORS` is missing/mistyped. Add it and redeploy, or add corridors in **Treasury** |
| Every transfer is held for review | Console → **Compliance → Sanctions** | No sanctions list loaded. Set `BOOTSTRAP_SANCTIONS_URLS` or import one. This is intentional: an empty list must never look like a clean screen |
| Customers get no SMS code | Render → Logs | `TWILIO_*` not set. Deployments log *"SMS not configured"* instead of sending |
| Webhook shows **rejected** | Console → **Compliance → Webhooks** | `FLW_WEBHOOK_HASH` does not match the secret hash in the Flutterwave dashboard |
| Sign-in says *"Cannot reach the API"* | your `/admin` page | You are on the login page of a stopped service, or Render redeployed — refresh in a minute |
| App cannot reach the API | EAS build summary | `EXPO_PUBLIC_API_URL` secret is wrong or missing a `/api/v1` suffix. Set it, then re-run the workflow |
| *"Four-eyes violation"* when approving | Console → Maker-checker | You raised the request yourself. A different operator must approve it — that is the control working |

## What each service costs at this scale

* **Supabase** — free tier is fine to start; Pro (~$25/mo) adds daily backups and
  PITR.
* **Render** — free web service works for staging (it sleeps after 15 minutes of
  inactivity, so the first request is slow). For production use Starter
  (~$7/mo) so the API is always awake and customer transfers are never delayed.
* **Expo/EAS** — free tier includes a limited number of builds per month;
  Production is ~$19–99/mo depending on plan.
* **Twilio** — pay per SMS (~$0.05 per OTP in Qatar).
* **Flutterwave / Ria** — per-transaction fees agreed with them.
